# v1.1.9 Experimental - Interlace conversion

This build adds **Tools > Convert Interlace (experimental)...** for validating a real pixel-layout conversion before it is integrated into normal PNG Replace.

## What it does
- Converts the selected indexed texture between the BGRA/linear family and the PS2/swizzled family.
- Preserves the Normal/Inverted flag automatically: `0 <-> 2` and `1 <-> 3`.
- Reorders only pixel indices. It does not quantize the image and does not rebuild or alter the CLUT.
- Uses the normal automatic `.bak` protection before changing the TPL.

## Safety restrictions in the experimental build
- 8-bit: supports the usual rectangular and square dimensions covered by the current PS2 mapping.
- 4-bit: limited to square textures, 32x32 or larger, in 32-pixel steps. The old decoder uses a transposed work surface for other shapes and those cases are intentionally blocked until verified.
- Textures with mipmaps are blocked because this experiment converts only the base texture.
- The legacy decoder currently treats 0/1 alike and 2/3 alike, so this experiment preserves the existing Normal/Inverted bit instead of trying to redefine it.

## Recommended test
1. Make a copy of a known-good TPL (automatic backup is also enabled).
2. Select an 8-bit BGRA texture without mipmaps.
3. Tools > Convert Interlace (experimental) > PS2.
4. Close/reopen the TPL and inspect the preview.
5. Test in Resident Evil 4 PS2.
6. Convert the same texture back to BGRA and compare it with the original.
7. Repeat with a supported 4-bit square texture.

If round-trip and in-game tests succeed, the same swizzle stage can be integrated into PNG Replace/Batch Replace so imports preserve the target texture interlace automatically.
